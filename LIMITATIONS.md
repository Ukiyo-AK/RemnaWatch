# Ограничения Domain Activity Monitoring

- Соединение/accepted log event не означает посещение страницы, успешный запрос или завершённое соединение. Фоновое ПО, reconnects, multiplexing и UDP меняют смысл количества событий. Числа — зарегистрированные события, не уникальные посетители и не все сетевые сессии.
- Домен клиентского запроса может отсутствовать при IP destination. ECH скрывает внутренний SNI; outer SNI может принадлежать общему сервису. CDN, shared hosting и несколько доменов на одном IP исключают надёжное восстановление по адресу. DNS/PTR не выполняются. URL paths, HTTPS contents, пароли, cookies, payload не сохраняются.
- Sniffing HTTP/TLS/QUIC зависит от формата/версии/успеха разбора и не гарантирует домен в access.log. Исследование штатного внешнего API и ограничения экспорта приведены в ARCHITECTURE.md. Built-in сборщик не получает SNI/Host/FakeDNS metadata отдельно. Их source labels доступны только доверенному, отдельно реализованному producer с точной корреляцией.
- Не меняются маршруты, destination, sniffing, DNS или настройки Xray. Нет DPI, MITM, сертификатов, packet capture. При отсутствии access.log сбор невозможен. Включение access logging самим оператором имеет отдельную стоимость, которую нельзя назвать нулевой.
- access.log может не содержать inbound tag, email, исходный client IP, outbound или точный destination IP. Без точного user mapping событие не включается в пользовательскую историю. Для inbound-less строк mapping должен явно использовать такой источник; текущий UserMap требует непустой inbound, поэтому они отбрасываются. Peer IP может быть proxy IP. Домен из лога по умолчанию имеет неизвестное происхождение.
- Парсер поддерживает документированные строковые accepted TCP/UDP записи с датой `YYYY/MM/DD HH:MM:SS[.fraction]`, detour и email; fractional часть отбрасывается до секунды. Другая версия/JSON формат требует нового parser adapter. Timezone фиксируется явно; DST/смена timezone требуют корректировки источника. Clock skew и timestamps более 60 секунд в будущем не импортируются.
- Детали доступны 7 дней, агрегаты 30 по умолчанию. Агрегаты сохраняют секунду и измерения кроме client IP/event ID, поэтому при высокой кардинальности размер близок к событиям. Запросы ограничены 2 секундами; большие диапазоны могут вернуть 503. Нужны дисковое квотирование и мониторинг lag в deployment. 30 000 событий в unit test проверяют корректность пакетной обработки, но не доказывают производительность production Xray.
- Бounded polling может отставать от лога: примерно batch_lines/poll_seconds строк в секунду. Пропущенные между polls ротации, copytruncate races, удалённые непрочитанные файлы и аварийный restart после rename могут потерять данные. Anchor выявляет часть rewrites, но одинаковая перезапись файла не всегда обнаружима. Oversized/повреждённые строки и unknown users объединены в счётчике; точная полнота не вычисляется.
- Dedup работает в пределах aggregate retention и стабильного source ID. Для двух независимых источников без общего connection ID нельзя безопасно считать уникальные соединения; не включайте оба для одной сессии. Metadata API не поддерживает позднее обновление существующего события: producer должен отдавать окончательное событие, иначе retry игнорируется.
- Exact domain/connection traffic обычно недоступен в access.log; bytes=null. Счётчики пользователя не распределяются по доменам. Network context — измерение всего выбранного host interface, не доказанный вклад пользователя или домена. Сопоставление по времени не доказывает причину нагрузки.
- Автоматическое удаление очищает рабочие таблицы и WAL (secure_delete, checkpoint), но не исходный log, backups, filesystem snapshots или ранее выгруженные ответы. Purge не гарантирует forensic erasure на SSD. Защита файлов/backup и reverse proxy — обязанность оператора.
- В исходном репозитории не было другого API/auth и Remnawave connector. Поэтому предоставлены общая авторизация самостоятельного сервиса и explicit mapping, без вымышленной интеграции с отсутствующим API. Токен сервисный с доступом к полной истории; tenant/user RBAC должен обеспечивать backend панели.
